## 1. WHAT THIS SESSION DELIVERED (verified, not asserted)

### Shutdown-signal fix (THE active task this session)
**Symptom:** `run.py the-smallest-kitten-cravings --queue` ignored SIGTERM/SIGINT during a crawl — the process kept running after the signal (confirmed live: a running crawl pid stayed alive after `kill -TERM`).

**Root cause (two layers):**
1. The old handler only set `_cancel_requested["flag"] = True`, which nothing ever read → dead no-op.
2. My first fix installed `loop.add_signal_handler(...)` *after* `await queue_mode(...)` returned. Since `queue_mode` does NOT return until the crawl ends, there was no handler during the entire crawl → SIGTERM hit Python default → hang.

**Correct fix (implemented + verified):**
- `run.py` `_run()`: create caller-owned `wall_halt = asyncio.Event()` **before** the crawl; register `loop.add_signal_handler(SIGINT/SIGTERM, _request_shutdown)` **before** `await queue_mode(...)`; pass that same `wall_halt` into `queue_mode`.
- `queue_integration.py`: `_drain_queue(...)` and `queue_mode(...)` accept optional `wall_halt: asyncio.Event | None = None`; `_drain_queue` reuses the caller's event (creates its own only if `None`). The coordinator already calls `wall_halt.set()` on completion/login-wall (line ~401) and workers honor it, so an external signal cleanly releases everything.
